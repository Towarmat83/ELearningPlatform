# Plan: Merge Quiz API into Module API

## Goal
Define quizzes inline within modules in the Course CRD, eliminating the separate quiz YAML file loading mechanism. Quizzes become a first-class module type alongside video, text, and image.

## Current State Analysis

### Modules (in CRD)
- Defined in `spec.modules[]` with types: `video`, `text`, `image`, `quiz`
- For `quiz` type, uses `quiz_ref` field pointing to external QuizStore
- Accessed via `/api/courses/{slug}/modules` and `/api/courses/{slug}/modules/{index}`

### Quizzes (separate system)
- Loaded from YAML files into `QuizStore` via `LoadDir()`
- Own API: `/api/courses/{slug}/quizzes`, `/api/courses/{slug}/quizzes/{quiz_id}`, `/api/courses/{slug}/quizzes/{quiz_id}/submit`
- `Covers` field links quiz to courses/modules (reverse linking)

## Implementation Plan

### Phase 1: Update Data Models

#### 1.1 Update `ModuleYAML` and `Module` types (`internal/content/types.go`)
- Add inline quiz fields to `ModuleYAML`:
  - `questions[]` (array of questions with all current QuizYAML.QuestionYAML fields)
  - `passing_score`
  - `cooldown` (strategy, base_seconds, multiplier, max_seconds)
  - `max_attempts_per_question`
  - `lock_on_max_attempts`
  - `version`
- Add `Questions []QuestionYAML` to `Module` struct
- Add `QuizMetadata` struct (passing_score, cooldown, etc.) to `Module`

#### 1.2 Update `k8s.go`
- Extend `crdToCourse()` to parse inline quiz fields from CRD
- Store inline questions in `Module.Questions` and quiz metadata
- Remove the `QuizRef` -> `QuizStore.Get()` enrichment logic (no longer needed)

### Phase 2: Remove Separate Quiz Loading

#### 2.1 Update `main.go`
- Remove the `QuizStore.LoadDir()` call
- Remove `QuizStore` field initialization (keep only for cooldown tracking)

#### 2.2 Update `state.go`
- Remove `QuizStore` from `State` struct (no longer needed for fetching)
- Keep `CooldownTracker`

### Phase 3: Unify Handlers

#### 3.1 Update `modules.go`
- `ListModules`: For quiz-type modules, include `question_count` in response
- `GetModule`: For quiz-type modules, include inline quiz detail (questions, passing_score, cooldown settings)
- The `Viewed` tracking still works via lesson_slug mapping

#### 3.2 Remove `quiz.go` handlers
- Delete file or repurpose for quiz-specific logic only
- Move submission endpoint to module path

#### 3.3 Update `router.go`
- Remove `/api/courses/{slug}/quizzes*` routes
- Add quiz submission to module routes: `POST /api/courses/{slug}/modules/{index}/submit`

### Phase 4: Update Scoring System

#### 4.1 Update `scoring.go`
- Add `ScoreModuleQuiz(module *Module, answers)` function
- Reuse existing `ScoreQuiz` logic by converting Module.Questions to Quiz format

#### 4.2 Update cooldown tracking
- Keep `CooldownTracker` but adjust keys to use `module:index:question_id` pattern
- Update `SubmitQuiz` to work with module-based keys

### Phase 5: CRD YAML Example

```yaml
apiVersion: elearning.example.com/v1
kind: Course
metadata:
  name: kubernetes-basics
spec:
  title: "Kubernetes Basics"
  modules:
    - name: "Kubernetes Quiz"
      type: "quiz"
      passing_score: 80
      max_attempts_per_question: 3
      lock_on_max_attempts: true
      cooldown:
        strategy: "exponential"
        base_seconds: 30
        multiplier: 2.0
        max_seconds: 3600
      questions:
        - id: "q1"
          type: "single"
          difficulty: "medium"
          points: 2
          question: "What is the smallest deployable unit in Kubernetes?"
          answers:
            - id: "a"
              text: "Pod"
              correct: true
            - id: "b"
              text: "Container"
              correct: false
          feedback:
            correct: "Correct! Pods are the smallest deployable units."
            wrong: "Incorrect. Pods are the smallest deployable units in Kubernetes."
```

## API Changes Summary

| Old Endpoint | New Endpoint |
|-------------|--------------|
| `GET /api/courses/{slug}/quizzes` | (integrated into modules list) |
| `GET /api/courses/{slug}/quizzes/{quiz_id}` | `GET /api/courses/{slug}/modules/{index}` (returns quiz detail for quiz type) |
| `POST /api/courses/{slug}/quizzes/{quiz_id}/submit` | `POST /api/courses/{slug}/modules/{index}/submit` |

## Benefits

1. **Single source of truth**: All course content including quizzes defined in CRD
2. **Simpler architecture**: No separate quiz file loading or `QuizStore` needed
3. **Better encapsulation**: Quizzes are clearly part of module sequence
4. **Easier management**: All course structure visible in one place

## Migration Notes

- Existing quiz YAML files can be converted to inline module definitions
- The `Covers` field logic becomes unnecessary (quiz is already in module list)
